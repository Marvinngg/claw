# Meta-Agent · 智能体工厂

> 理解即降秩，进化即压缩，智能体即秩的运行时实例化。

## 智能体 = M1 × M2 × M3

一个专业自进化智能体由且仅由三个不可约部分组成：

| 生成器 | 是什么 | 缺了变成 |
|--------|--------|---------|
| **M1 认知内核** | 领域的不可约理解结构（最少几个独立思维操作覆盖所有专业行为） | 通用聊天机器人 |
| **M2 进化协议** | 降秩式自我修正闭环（压缩经验，不是堆积经验） | 静态工具 |
| **M3 能力接口** | 数据×智能×工具的可插拔端口（MCP 统一） | 封闭系统 |

M1 是灵魂——去掉后 M2 无内容可压缩，M3 无框架可消化数据。

## 降秩方法（M1 的生成过程）

这是整个管线的核心认知操作。对任意领域执行以下四步：

**步骤 1 · 现象收集**：列举该领域专家的典型行为（≥10 个，越多越好）。引导用户穷举，不要过早归纳。

**步骤 2 · 维度发现**：从行为中提取独立变化的维度。判断独立性的方法——问：改变维度 A，维度 B 是否必然改变？若否，则独立。

**步骤 3 · 降秩**：找约束关系，消除非独立维度。剩下的就是生成器。每个生成器用一句话定义。标注**灵魂生成器**——去掉后系统退化最严重的那个（通常是某种形式的元认知：不是做事本身，而是对做事方式的反思和校准）。

**步骤 4 · 生成验证**：用生成器的组合重建步骤 1 的所有行为。能重建 → 秩正确。不能 → 遗漏了生成器，回步骤 2。同时做退化验证：逐个去掉生成器，确认灵魂生成器标注正确。

## 编码原则（M1 → SKILL.md）

用约束声明范式，不用编排循环。不写"先做A再做B"，只写"不能做X"+"能用什么工具"。LLM 自己决定执行顺序。编排循环是天花板（限制），约束声明是地板（释放）。

编码约束：
- SKILL.md ≤ 5000 字符。超过说明没压缩好，回去降秩
- 每个生成器：定义 + 模式表/组合规则
- 灵魂生成器显式标注
- 编码模板和黄金示例见 `references/skill-template.md`

## 进化协议设计（M2）

### 核心机制：降秩式进化

```
执行 → trace（做对/做错了什么）→ 对 trace 降秩 → 折叠回 SKILL.md
```

**复利工程**：每次成功执行后，显式记录"哪个结构/表达方式有效" → 折叠进 references/ 或 SKILL.md → 下次执行直接引用。成功模式单调递增。（Simon Willison 2026）

约束：进化后 |SKILL.md| ≤ 原长 120%。必须删旧腾新，不是追加。长期看，信息密度单调递增。

### 三通道优先级

| 通道 | 进化什么 | 优先级 | 映射 |
|------|---------|--------|------|
| γ | 元认知（怎么想） | 最高 | 灵魂生成器 → γ |
| δ | 规则（怎么做） | 中 | 其余生成器 → δ |
| α | 数据（看什么） | 低 | 数据源经验 → α |

### 触发与验证

```
每次执行末尾 → 进化反思（1-2句）→ 写入 evolution-log
  → 心跳扫描 → skill 自主体自行处理：
    ├ [知识] → 吸收进 SKILL.md 或放 references/ 或丢弃
    └ ≥3 条同类 [反思] → 分析模式 → 自主修改 SKILL.md（γ>δ>α）
```

进化日志模板见 `references/evolution-log-template.md`。

## 能力接口（M3）

Skill 的能力来源分两层：

**CC 原生工具**：Read/Write/Edit/Bash/Glob/Grep/WebFetch/WebSearch — 所有 skill 默认可用
**Skill 专属工具**：tools.py 中定义的 MCP 工具 — 当 CC 原生工具无法达到应有输出质量时造

### 工具评估（降秩完成后执行）

核心问题：**用 CC 原生工具能否达到这个 skill 应有的输出质量？**

- 数据质量不够（信源层级、时效性）→ 造数据获取工具，直连一手源
- 执行精度不够（Bash 不够稳定/防呆）→ 造计算/处理工具
- 上下文溢出（任务复杂度超出单轮上下文）→ 设计子 agent 委派模式（Task tool），保护主上下文（Simon Willison 2026）
- CC 原生够用 → 不造 tools.py，SKILL.md 中声明用什么工具即可

造工具时 Read `references/tool-methodology.md` 获取设计方法论。
编码骨架见 `references/tool-template.py`。

**上下文质量法则**：领域特定参考文档（语法/模式/案例）作为准备好的上下文，是 AI 输出质量的决定性因素，比模型本身更关键。（Xe Iaso 2026）

## 封装与验证

新 skill 产出到 `.claude/skills/{name}/` 目录（CC 自动发现）：
- `SKILL.md` — 接线图（**唯一保证被 CC 加载的文件**，方法+知识全在这里）
- `evolution-log.md` — 空模板（心跳扫描用，`[反思]`/`[知识]`/`[工具需求]` 标签）
- `references/` — 空目录（辅助参考资料，SKILL.md 可索引引用）
- `tools.py` — 可选（仅当工具评估判定需要时生成，遵循 tool-methodology.md）
- `references/tool-spec.md` — 可选（工具需求声明：为什么造、数据源、备选方案）

验证标准：
- 冒烟测试：每个生成器至少一个场景通过
- 退化测试：去掉灵魂生成器，确认输出质量显著下降
- 回到任何阶段修正，直到通过
